- M0.5: STANDING RULE — after any visual change, run the harness and VIEW the PNGs before declaring done.
- M1: dependency added — `three-mesh-bvh@0.9.11` (runtime): BVH over the merged static level geometry; powers raycasts now (ground probe, click-to-copy) and the M2 capsule sweep next. Hand-rolling a BVH is weeks of work for a worse result; this is the one collision dependency SPEC §8.1/§8.3 sanctions.
- M1: toolchain verdict — KEEP Vite 8. The Mac install failure's root cause was npm < 10.9's optional-deps bug (npm/cli#4828), not vite; vite 7 also ships native binaries (esbuild) and exits support sooner. Mitigation instead of downgrade: package.json "engines" (node ≥ 22.12, npm ≥ 10.9) + .npmrc engine-strict=true, so an old toolchain fails at install with a clear EBADENGINE instead of a cryptic rolldown crash at dev time.
- M1: ramp convention — the wedge's bounding box centres on `pos` exactly like a box; the slope rises along local +Z (bottom edge at -Z, full height at +Z); `rotY` (degrees, CCW around Y) orients it. Proven by collider unit tests (slope height at z=0 is exactly h/2).
- M1: F2 draws the merged collision geometry as an X-ray wireframe (depthTest off), not the BVH boxes — levels are authored against surfaces, not the tree.
- M1: the level validator ignores unknown top-level keys (tokens/props/shards/goal) so M4 content can sit in the JSON before its systems exist; env gains optional `sunIntensity` (default 1.0) so light intensity isn't a hardcoded number.
- M1: scaffold tuning slimmed to `cubeSize`; the camera-target cube now uses palette "accent" and is placed by `collider.groundProbe` under the level spawn — the probe is exercised on every boot.
- M1: all goldens re-blessed (the scene is now level01; the M0 scaffold scene is retired); the level01 golden is framed to include all five blocks for maximum regression coverage.
- M1: fixed rename artifact in CLAUDE.md — "stillmotel Cores" → "elemental Cores" (the ELEMENTA→STILLMOTE sed over-matched "elemental").
- M2: collision is move-then-depenetrate (bvh shapecast, segment-vs-triangle push-out), NOT a true swept capsule — per owner ruling the thin-platform tunnelling test is the arbiter: it passes at maxFallSpeed against 0.1-thick geometry and the raw sweep holds to ~2× beyond (60 m/s). Sub-moves are clamped to radius/2, which keeps the bottom sphere on the correct side of any face (push-out is always outward). If M4 forces ever exceed that envelope, revisit — the test will say so.
- M2: jump fires BEFORE gravity in the update order, so a full-hold apex undershoots jumpHeight by ~v·dt/2 (semi-implicit Euler) instead of overshooting; tests assert full-hold ≈ h tightly AND early-release strictly lower (owner correction — the two must not be satisfiable by one loose assertion).
- M2: ground snap on slopes rests the capsule at hit.y + r(1/n.y − 1) — snapping to the raw probe hit sinks the capsule into inclines (found by the 45° slope test, not by eye).
- M2: air acceleration = accelAir × airControl (SPEC defines both but not their composition); look-ahead is horizontal-only (owner-flagged, approved); interpolation covers position + yaw, pose (squash/lean/bob) uses latest sim state.
- M2: chassis proportions beyond radius/height are structural constants in ChassisBuilder/Sockets (owner-approved; the visor is expected to migrate to tuning when the face gets fiddled with). All ten §3.2 sockets exist, empty.
- M2: TUNING additions [M2+]: player.anim (idleBobAmp .03, idleBobPeriod 2.2, leanMaxDeg 12, leanStiffness 10, runThreshold .5, landDuration .12), player.landingBlob (radius .3, opacity .35), render.shadow (mapSize 2048, bias −0.0005). scaffold.* removed — the red cube is retired, the player is the camera target.

- M2 feel-fix A: the ramp-jump bug was the ground() vy-sign guard conflating jump-rise with slope-climb-rise (slide projection produces small +vy climbing); replaced with a post-jump snap-suppression timer (tuning.player.jumpSnapSuppress 0.1). Grounding now allowed at any vy outside the window; vy zeroed while grounded; crests exited horizontally (VP-accepted). Arbiter test includes the continuity assertion: grounded true EVERY step while climbing a walkable slope.
- M2 feel-fix A, deeper than diagnosed: the old build ALSO flickered on FLAT ground (state was 'land' at step 30 of a flat run — floor-box triangle-seam contacts produced micro +vy) — phantom-airborne frames interleaved air-accel and fired spurious land-squashes mid-run. The fix removes both; flat-ground velocities are bit-identical but the position trace advances slightly faster (uninterrupted ground accel). All moving goldens re-blessed for this reason.
- M2 feel-fix B1: pose channels (scale/lean/bob) now keep prev/curr pairs and interpolate by the render alpha like the position — a 60Hz pose stairsteps on any other refresh rate and read as jitter. Zero tuning changes; harness renders alpha=1 so goldens show pure sim state.
- M2 feel-fix B2: land-squash gated on fall speed at impact ≥ tuning.player.squash.minImpactSpeed (3), implemented in Player from the previous step's vy — controller untouched. Real jump-fall landings (~12 m/s) keep the full squash (visually confirmed in jump_arc_105). B3 (bob retune + speed fade) HELD for the VP.
- M2 feel-fix observation for the VP: 45° slopes climb slowly (~0.6 m/s vs 6.5 flat) because grounding zeroes the slide's up-slope component each step; the level's real 18° ramp climbs at near-full speed. If steep-slope climb speed ever matters, the lever is slope-plane velocity projection — a future feel decision, not taken unilaterally.
- M3 RULING (recorded verbatim): statMods are ABSOLUTE OVERRIDES, not multipliers. The §9 values prove the intent: Wind's fallGravityMult 1.15 must REPLACE base 1.6 (slower fall). As a multiplier it would give 1.84 — faster fall, the opposite of Wind. Stacking = apply loadout in order, later element's override wins per key.
- M3 RULING: tint lerp ticks on RAW step time (fixed 0.35s envelope) — dilation slows the world so the moment feels big, but the character's own change punches through at full speed. Unit-tested (dilated world dt, unscaled tint).
- M3: time dilation is ONLY a scale on the dt handed to sim consumers (player + updatables); PickupFx ticks on raw step time and the accumulator/fixed step never see dilation. Proven: pickup script through the whole dilation window reproduces at 0 px across independent harness runs.
- M3: loadout eviction at MAX_ACTIVE = swap-oldest (never reject); grant→revoke reversibility is a tested contract — stats deep-equal base, tint returns to #F2EDE4, sockets empty, zero residue (swap-puzzles depend on this).
- M3: Player.ts is element-BLIND — it iterates ElementModule data (tint hex, stat overrides, attachment specs) and never names an element; adding an element = one module file + one line in config/elements.ts. Player.test.ts uses ELEMENT_IDS indices so even tests contain no element literals.
- M3: WindModule carries ONE test-fixture attachment (tilted torus at orbitHigh) purely to prove attach/follow/animate/detach — NOT art, NOT the Wind visual (M5 replaces it). SPEC's "attachments: []" deviation is deliberate: an untested attachment system can't ship.
